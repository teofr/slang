NatSpec Lexing Benchmarks

PR 2255 lexes each /// line separately and merges consecutive lines in the token stream. In review, Omar suggested three follow-ups. This page benchmarks each one (plus a variant called 1b, and the combination) on its own branch in teofr/slang. It closes with an independent review of the changes.

Summary

  • PR 2255 costs +2.20% parser instructions against its merge base. Merge base and current main are identical on the parser stage (±0.00%). No other stage moves, and allocations are unchanged.
  • Skipping trivia in the lexer (option 1 / 1b) is where the speed comes from: −2.88% / −2.94% on top of the PR. The pending-field refactor (2) gives −0.32%, and the range change (3) gives nothing.
  • All three together give −3.84% against the PR, which matches Omar's "3–4%". Against the merge base that is −1.72%.
  • Trivia skipping works on main too. Option 1 gives −1.82%. Option 1c, which skips all regular trivia (main already merges /// lines in its lexer, so it needs none of them), gives −2.12%.
  • On equal footing, PR 2255 costs about +0.41% of parser instructions: combined against main + 1c, between +0.28% and +0.63% per contract. That is about 0.2% of the whole pipeline.
  • With the right reader and PR 2254, the cost drops to +0.03%. PR 2254 forces next_lexeme inline. Combined with an outlined comment reader, the PR matches main + 1c + 2254. On top of the pending-field design, 2254 is unnecessary (+0.27%) unless the NatSpec handling is marked #[cold] (option 2b, +0.36%). See "Inlining" below.

Forcing next_lexeme inline only pays off when the NatSpec handling is outside the hot loop. With the pending field inline, 2254 makes things slightly worse. #[cold] alone does nothing (−0.09% against combined) but recovers most of the gain together with 2254. Every branch carries two CI-only commits so benchmark_cargo_slang_v2 runs a dry run on bench/** pushes without a Bencher key. Parser tests and all 812 CST and binder snapshots pass locally on each code branch. The diagnostics snapshots need a solc download that this environment blocks.

Method

  • slang_v2 gungraun suite (Callgrind and DHAT), one dry run per branch on ubuntu-24.04 GitHub runners. Numbers are taken from each job's log.
  • 54 benchmarks: 6 pipeline stages × 9 contracts. Only the parser stage times parsing; the others parse in setup and moved by at most 0.006%.
  • Instruction counts are deterministic. Merge base and main are equal on the parser stage (±0.005%), which sets the noise floor.
  • Raw logs, parsed metrics and these tables are committed to bench/2255-results in teofr/slang.

Independent review

Written by a separate Claude agent (Fable) that read every diff and the raw results without editing anything. Its factual claims about the numbers and about main were re-checked before publishing.

Correctness

  • The PR's CommentReader matches solc: the last comment wins, a blank line or any other comment splits a /// run, //// is a regular comment, and regular comments don't drop a pending doc comment. Checked: \r-only and CRLF endings, /// at end of file, /** */ after ///, lexical-context switches, unrecognized lexemes.
  • The 1b gap check is equivalent to the PR's state machine. Every skipped // or /* */ contains a /, and a second line break contains \n or \r. So "one line break plus spaces or tabs" holds exactly when the PR would merge. No input was found where they differ.
  • Not introduced here: solc ends a /// line at form feed or vertical tab (\x0b, \x0c), while slang's [^\r\n]* runs through them. Worth a test.

Code improvements

  • A per-item skipped = true in the language definition leaks a lexer detail into the language model, and nothing validates it: setting it on a NatSpec item would silently break NatSpec. Either skip every trivia that isn't a NatSpec comment as a code-generation policy, or add a check that rejects skipped on NatSpec items. The FilterResult::Skip callback is fine compared with #[logos(skip)].
  • Skipped lexeme kinds are still generated but never produced. That's acceptable if the skipping is temporary; otherwise stop generating them.
  • Once the lexer skips trivia itself, rename NonTriviaTokens. Add unit tests for is_line_continuation ("\n", "\r\n ", "\r", "\n\n", "\n/* x */ ", "").
  • The PR commit has no body. Write down why the merging regex was reverted, since the benchmark doesn't argue for it.

Benchmark validity

  • Single deterministic runs are enough for instructions. The 11-commit gap between the PR base and main doesn't bias the parser numbers.
  • The review called combined against main with option 1 (+0.10%) the fair comparison. Option 1c, measured afterwards, is the stricter baseline: +0.41%.
  • Option 2's large cycles gain, and the combination beating the sum of its parts (−3.84% against −3.26%), are likely inlining and layout effects that could flip with a toolchain update.

Architecture

  • The token stream is the right place to merge NatSpec. The regex the PR reverted needed four fragments per context and couldn't express "only the last comment counts".
  • A lexer that drops trivia is a step back for a full-fidelity CST tool, and the gain goes away when trivia comes back. It is cheap to undo and harmless meanwhile, but it should be labeled temporary and land separately.

Recommended path

  1. Rebase PR 2255 on main. Fold in 2, 3 and 1b's merge-by-source-gap reader, which only needs the source text, not lexer skipping. Write the motivation in the PR body and add the gap unit tests.
  2. Separately, open a small PR "lexer: skip non-NatSpec trivia (temporary, until trivia is in the CST)" with the code-generation change, so it can be reviewed and reverted on its own.
